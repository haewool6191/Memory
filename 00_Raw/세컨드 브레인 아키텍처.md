


## 🧠 세컨드 브레인 아키텍처 (Second Brain Architecture)

**핵심 주제:** 개인의 지식 관리 시스템(Personal Knowledge Management, PKM)을 구조화하고 자동화하여, 실제 뇌가 정보 저장 및 검색에 소모하는 에너지를 줄이고 창의적 사고에 집중할 수 있도록 설계하는 체계적인 방법론.

---

### 💡 개요 (Overview)

세컨드 브레인은 단순한 메모 앱이나 파일 폴더가 아닙니다. 이는 **'생각하는 시스템(Thinking System)'** 그 자체입니다. 외부 저장소(디지털 또는 아날로그)를 개인의 인지적 확장 도구로 활용하여, 아이디어의 포획(Capture), 연결(Connection), 정제(Refinement), 출력(Output)이라는 지식 순환 과정을 체계적으로 관리합니다.

---

### 🧱 핵심 구성 요소 (Core Components)

성공적인 세컨드 브레인 아키텍처는 다음 네 가지 기능을 유기적으로 통합합니다.

**1. 포획 (Capture / Inbox):**
*   *기능:* 외부에서 들어오는 모든 정보(아이디어, 기사, 할 일, 생각 등)를 즉각적이고 마찰 없이 수집하는 단계.
*   *목표:* "잊어버릴 것"이 없는 안전한 임시 저장소 구축.

**2. 정리 및 구조화 (Organize / Storage):**
*   *기능:* 포획된 정보를 목적과 중요도에 따라 분류하고, 상호 연결하는 단계. (단순 폴더링을 넘어선 '관계'의 설계)
*   *핵심:* 정보 간의 연결고리(Links)를 만들어 지식의 네트워크를 구축.

**3. 처리 및 정제 (Process / Synthesis):**
*   *기능:* 저장된 조각난 정보(Notes, Snippets)들을 취합하고, 자신만의 언어로 재해석하여 통찰(Insight)을 도출하는 단계.
*   *대표 방법론:* Zettelkasten(제텔카스텐) 방식 적용.

**4. 출력 및 활용 (Output / Action):**
*   *기능:* 정리된 지식을 바탕으로 실제 결과물(글, 발표, 프로젝트, 의사결정)로 전환하는 단계.
*   *목표:* 지식 축적을 '결과물 생성'으로 연결하여 가치 창출.

---

### 🛠️ 주요 접근 방식 및 방법론 (Methodologies)

어떤 시스템을 구축할지 결정하는 프레임워크입니다.

| 방법론 | 주요 특징 | 적용 목표 | 적합한 사용자 |
| :--- | :--- | :--- | :--- |
| **PARA Method** (Tiago Forte) | Project(프로젝트), Area(영역), Resource(자원), Archive(보관소)의 4가지 명확한 분류 체계. 행동 지향적. | 정보의 '행동 가능성'에 따른 즉각적인 분류와 관리. | 생산성 최적화 및 프로젝트 기반 업무 사용자. |
| **Zettelkasten** (Niklas Luhmann) | 작은 단위의 원자적 노트(Atomic Note)들을 서로 연결하고 참조하며 지식 네트워크를 구축. | 지식의 '연결성'과 '통찰력' 증진. 단순 저장소를 넘어선 사고 도구. | 연구자, 작가, 깊이 있는 사색을 원하는 사용자. |
| **GTD (Getting Things Done)** | 모든 할 일과 아이디어를 외부 시스템에 쏟아내고, '다음 행동(Next Action)'으로 정의하여 관리. | 업무와 일상의 '흐름'을 체계적으로 관리하고 실행력을 높임. | 관리자, 멀티태스커, 업무가 많은 직장인. |

### 💻 추천 도구 및 플랫폼 (Tools & Platforms)

아키텍처를 구현하는 데 사용되는 소프트웨어들입니다. 도구 자체보다 **사용 방식(방법론)**이 중요합니다.

*   **Obsidian:** 강력한 양방향 링크(Bi-directional Linking) 기능과 그래프 뷰(Graph View)를 통해 지식 간의 관계를 시각화하는 데 최적화됨. (Zettelkasten 구현에 강점)
*   **Notion:** 데이터베이스, 위키, 문서 통합 기능을 제공하여 PARA와 같은 구조화된 시스템을 구축하는 데 용이함. (구조화된 관리에 강점)
*   **Roam Research / Logseq:** 블록 기반의 노트 작성과 실시간 연결 기능에 특화되어 있어, 아이디어를 즉각적으로 연결하고 흐름을 파악하는 데 유리함.

**'워크스페이스 루트 폴더(Workspace Root Folder)'란 내가 현재 안티그래비티(Antigravity IDE)로 열어서 작업하고 있는 ‘프로젝트의 최상위(메인) 폴더’를 의미합니다.**

특별히 정해진 시스템 폴더가 아니라, **"내가 내 세컨드 브레인 메모들을 모아두기 위해 내 컴퓨터에 직접 만든 폴더"**가 바로 워크스페이스 폴더가 됩니다.

어디에 어떻게 만들고 세팅해야 하는지 가장 알기 쉽게 정리해 드릴게요.

---

📂 1단계: 내 컴퓨터 원하는 곳에 폴더 만들기 (추천 위치)

먼저 윈도우 탐색기를 열고, 관리하기 편한 위치에 빈 폴더를 하나 만듭니다.

- 윈도우 C 드라이브나 D 드라이브 상관없이 편한 곳에 만드시면 됩니다.
- **예시 경로:** `D:\MySecondBrain` 또는 `C:\Users\Owner\Documents\Brain`

---

🚀 2단계: 안티그래비티 IDE에서 이 폴더 열기

폴더를 만드셨다면, 이제 안티그래비티에게 *"여기가 내 세컨드 브레인 작업실이야"*라고 알려주어야 합니다.

1. **안티그래비티(Antigravity IDE)**를 실행합니다.
2. 왼쪽 상단 메뉴에서 **File(파일) ➡️ Open Folder(폴더 열기)**를 클릭합니다.
3. 방금 1단계에서 내가 만든 폴더(`MySecondBrain`)를 선택하고 **[폴더 선택]**을 누릅니다.
4. 이제 안티그래비티 화면 왼쪽 사이드바(Explorer)에 내가 만든 폴더 이름이 대문자로 크게 뜨게 됩니다. **이 상태가 되었을 때의 그 폴더 내부 공간을 '워크스페이스 루트'라고 부릅니다.**

---

📝 3단계: 매뉴얼 파일(`.antigravity-manual.md`)은 어디에 만드나요?

안티그래비티에서 폴더를 여셨다면, 그 안의 **비어있는 공간**에 바로 파일을 만드시면 됩니다.

1. 안티그래비티 왼쪽 사이드바(폴더 음영 공간)에서 마우스 우클릭 후 **New File(새 파일)**을 누릅니다.
2. 파일 이름을 **`.antigravity-manual.md`** 라고 정확히 입력합니다. (맨 앞에 점`.`이 붙는 숨김형 설정 파일 구조입니다.)
3. 생성된 파일 안에 앞서 안내해 드린 **[세컨드 브레인 시스템 프롬프트]** 내용을 그대로 복사해서 붙여넣고 저장(`Ctrl + S`)합니다.

네, 정확하게 짚으셨습니다! **'안티그래비티 전용 세컨드 브레인 시스템 프롬프트'라는 제목 설명글은 완전히 빼고, 그 아래에 있는 `[Role & Context]`부터 마지막 명령 줄까지만** 복사해서 넣으시면 됩니다.

📄 파일에 넣을 최종 내용

markdown

```
[Role & Context]
당신은 나의 로컬 지식 저장소를 관리하는 AI 사서(Librarian)이자 지식 아키텍트 에이전트입니다. 이 폴더(Brain) 내의 마크다운(`.md`) 파일들을 분석하고, 정제하며, 파일 간의 관계를 배선(Wiring)하는 것이 당신의 핵심 임무입니다.

[지식 저장소 규칙]
1. 모든 노트는 하나의 개념만 다루는 '원자 단위 노트(Atomic Note)'로 작성되어야 합니다.
2. 파일명은 띄어쓰기 대신 하이픈을 사용합니다 (예: second-brain-architecture.md).
3. 모든 노트는 본문 하단에 타 노트와의 관계성 링크를 반드시 포함해야 합니다.

[핵심 미션: 타입이 있는 연결 (Typed Links)]
새로운 메모나 글이 들어오면, 기존 마크다운 파일들을 분석하여 하단에 위키 링크([[파일명]]) 형식으로 연결하되, 반드시 아래 3가지 관계 중 하나를 명시하세요.
- supports (뒷받침): 기존 노트를 지지하거나 근거를 제공하는 경우
- extends (확장): 기존 개념을 더 심화하거나 범위를 넓히는 경우
- contradicts (반박/대조): 기존 내용과 모순되거나 대조적인 관점을 제시하는 경우

[수행 프로세스 명령]
내가 새로운 마크다운 텍스트를 주거나 원시 메모 파일을 지정하면 다음 단계를 자동으로 수행하세요:
1. 핵심 추출: 입력된 텍스트에서 가장 중요한 원자적 아이디어를 도출합니다.
2. 중복 검사: 폴더 내 기존 파일 중 이미 동일한 주제를 다룬 파일이 있는지 확인합니다. (있다면 기존 파일 내용을 업데이트/extends 합니다.)
3. 새 파일 생성 및 배선: 새로운 파일이 필요하다면 생성하고, 파일 맨 아래에 기존 파일들과의 관계(supports, extends, contradicts)를 분석해 위키 링크를 자동 생성하세요.
```

코드를 사용할 때는 주의가 필요합니다.

🛠️ 해결 방법: 윈도우 시작 프로그램 완전히 바로잡기

1단계: 기존의 잘못 켜진 자동 실행 앱 끄기

1. 윈도우 작업 표시줄 오른쪽 아래(시계 옆 삼각 트레이)에서 **Ollama 아이콘(라마 모양)**을 마우스 우클릭합니다.
2. **[Quit Ollama]**를 눌러 완전히 종료합니다.

2단계: 환경 변수가 반영된 '진짜 자동 실행 바로가기' 만들기

윈도우가 켜질 때 환경 변수 주소(`0.0.0.0:11434`)를 강제로 주입하면서 Ollama를 실행하도록 가짜 시작 프로그램을 만들어 줄 것입니다.

1. 바탕화면 빈 곳에 마우스 **우클릭 ➡️ 새로 만들기 ➡️ 바로 가기**를 누릅니다.
2. 항목 위치 입력 칸에 아래의 코드를 **그대로 복사해서 붙여넣고** [다음]을 누릅니다.

    text

    ```
    cmd.exe /c "set OLLAMA_HOST=0.0.0.0:11434 && start "" "%LOCALAPPDATA%\Ollama\ollama app.exe""
    ```

stream 옵션은 어디서 켜요?

안티그래비티(Antigravity)와 LM Studio/Ollama 연동 환경에서 **Stream(스트리밍) 옵션을 켜는 방법**은 ==어떤 화면을 사용하고 계시는지에 따라 크게 **2가지 위치**에서 설정할 수 있습니다==.

현재 사용 중이신 환경에 맞는 방법을 선택해 보세요!

---

방법 1: `mcp_config.json` 설정 파일에 주입하기 (가장 추천)

안티그래비티가 백엔드에서 로컬 서버와 통신할 때 처음부터 스트리밍(한 글자씩 끊어 보냄)을 강제하도록 설정 파일에 옵션을 심어버리는 방법입니다.

1. 이전에 찾으신 진짜 설정 파일 주소인 **`C:\Users\Owner\.gemini\config\mcp_config.json`** 파일을 메모장으로 엽니다.
2. `env` 항목 안에 **`"LMSTUDIO_STREAM": "true"`** 또는 **`"OLLAMA_STREAM": "true"`** 옵션을 아래와 같이 추가해 줍니다. (두 개 다 넣어두면 어떤 로컬 서버를 쓰든 안전합니다.)

json

```
{
  "mcpServers": {
    "lmstudio-mcp": {
      "command": "python",
      "args": [
        "-m",
        "uv",
        "tool",
        "run",
        "--from",
        "git+https://github.com",
        "lmstudio-mcp"
      ],
      "env": {
        "LMSTUDIO_HOST": "127.0.0.1",
        "LMSTUDIO_PORT": "1234",
        "LMSTUDIO_STREAM": "true",
        "OLLAMA_STREAM": "true"
      }
    }
  }
}
```

코드를 사용할 때는 주의가 필요합니다.

3. 저장(`Ctrl + S`) 후 안티그래비티 IDE를 완전히 껐다가 다시 켭니다.

---

방법 2: Connect AI 확장 프로그램(Extension) UI에서 켜기

만약 안티그래비티 안에서 **Connect AI 플러그인 채팅창**을 주로 사용하고 계신다면, 익스텐션 자체 설정 UI에서 클릭 한 번으로 켤 수 있습니다.

1. 안티그래비티 IDE 왼쪽 사이드바에서 **Connect AI 플러그인 아이콘**을 클릭합니다.
2. 채팅창 우측 상단이나 하단에 있는 **톱니바퀴 아이콘(Settings)**을 누릅니다.
3. 설정 목록 중에서 **`Stream Response`** 또는 **`Enable Streaming`** 이라는 문구 옆의 체크박스를 체크(On)로 활성화합니다.
4. 만약 UI에 보이지 않는다면, 이전에 열었던 일반 설정(`Ctrl + ,`)을 누른 뒤 검색창에 `connectai stream`을 검색하여 해당 옵션을 `true`로 체크하셔도 됩니다.

💡 스트리밍이 켜졌는지 확인하는 법

설정을 마친 후 AI에게 *"안녕? 1부터 10까지 세어줘"*라고 질문해 보세요.
답변이 몇 초 동안 멈춰있다가 한 번에 퉁- 나오는 게 아니라, **내가 읽는 속도에 맞춰 실시간으로 글자가 주르륵 타이핑되듯 나온다면** 스트리밍 옵션이 완벽하게 적용된 것입니다!

설정 파일(`mcp_config.json`)에 옵션을 넣으셨나요, 아니면 Connect AI 플러그인 UI 설정을 확인하셨나요? 적용 후 글자가 실시간으로 부드럽게 잘 나오는지 알려주세요!

안티그레비티 를 끄니까 vscode 업데이트 에러가 나와요

안티그래비티(Antigravity IDE)를 껐는데도 **"Visual Studio Code가 실행 중이라 업데이트할 수 없다"**는 식의 에러가 뜨는 이유는 ==**안티그래비티가 내부적으로 VS Code를 기반으로 만들어진 프로그램이기 때문**==입니다. 

안티그래비티 앱 창을 닫았더라도, 백그라운드에서 실행되던 일부 엔진 프로세스(언어 서버나 터미널 등)가 좀비처럼 완전히 죽지 않고 파일들을 꽉 붙잡고 있어서(파일 락킹) 업데이트 설치를 방해하는 것입니다. [](https://discuss.ai.google.dev/t/latest-download-restart-to-update-error/127002)


이 문제를 말끔히 해결하고 정상적으로 업데이트를 완료하는 **가장 확실한 해결책 2단계**를 안내해 드립니다.

---

🛠️ 1단계: 백그라운드에 숨어있는 좀비 프로세스 강제 종료 (가장 빠름)

안티그래비티 관련 프로세스가 메모리에 남아있지 않도록 작업 관리자에서 확실하게 숨통을 끊어주어야 합니다.

1. 키보드로 `Ctrl + Shift + Esc`를 동시에 눌러 **작업 관리자**를 엽니다.
2. 상단 검색창이나 프로세스 목록에서 아래의 이름들을 찾아 마우스 우클릭 후 **[작업 끝내기]**를 누릅니다.
    - **`Antigravity`** 관련 프로세스 전체
    - **`Code`** 또는 **`Visual Studio Code`** 관련 프로세스
    - **`language_server_windows`** (이 녀석이 범인일 확률이 매우 높습니다) [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)

3. 좀비 프로세스들이 모두 사라졌다면, 에러 팝업창으로 돌아가 **[다시 시도(Retry)]** 버튼을 누릅니다. 막혔던 업데이트가 즉시 정상 진행됩니다. [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)

---

🛠️ 2단계: 그래도 안 된다면? 공식 독립 실행형 설치 (클린 해결법)

만약 작업 관리자에서 프로세스를 지워도 계속 에러 팝업이 뜨며 무한 루프에 걸린다면, 수동으로 덮어씌우는 것이 스트레스를 받지 않는 가장 깔끔한 정공법입니다. [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)

1. 컴퓨터를 **재부팅(다시 시작)** 합니다. (메모리에 꼬여있던 안티그래비티의 흔적이 완전히 깨끗하게 지워집니다.)
2. 부팅 직후 안티그래비티나 VS Code를 **절대 켜지 마세요**.
3. 안티그래비티 공식 홈페이지나 설치 파일([Antigravity Installer])을 다시 실행하여 업데이트 버전을 그대로 덮어쓰기로 설치해 줍니다. 기존에 쓰시던 세컨드 브레인 설정이나 마크다운 파일들은 전혀 지워지지 않으니 안심하셔도 됩니다. [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)

---

**💡 왜 이런 에러가 나나요?**
안티그래비티는 구글이 VS Code의 오픈소스 코드를 가져와 만든 IDE입니다. 그래서 자기가 에러를 뿜을 때 엉뚱하게 형제 프로그램인 `Visual Studio Code`라는 이름으로 경고창을 띄우는 일종의 버그성 표기 현상입니다. 프로그램이 꼬인 것이 아니니 당황하지 않고 프로세스만 죽여주시면 깔끔하게 해결됩니다. [](https://discuss.ai.google.dev/t/latest-download-restart-to-update-error/127002)
작업 관리자(`Ctrl+Shift+Esc`)에서 **`language_server_windows` 나 `Antigravity` 프로세스를 종료한 뒤 [다시 시도]를 눌렀을 때 업데이트가 정상적으로 완료**되었나요? 만약 여전히 특정 파일 경로를 대며 에러창이 사라지지 않는다면 **정확한 에러 문구**를 알려주세요! [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)


위에 2-1,2,3 프로세스가 없는데?

**목록에 프로세스 이름이 보이지 않는 이유는 윈도우가 그 프로세스들을 '세부 그룹' 안에 숨겨두었거나, 이미 백그라운드에서 백신 프로그램(Windows Defender 등)과 꼬여서 눈에 안 보이기 때문입니다.** [](https://discuss.ai.google.dev/t/antigravity-error-language-server-exe-binary-not-found-on-windows/190674)

눈으로 일일이 찾을 필요 없이, 윈도우 터미널 명령어로 찌꺼기를 한 번에 강제 청소하고 업데이트를 통과시키는 **가장 확실한 정공법**을 안내해 드릴게요. 딱 1분이면 끝납니다.

🛠️ 해결책: 파워쉘 명령어로 강제 청소하기

작업 관리자 창을 닫으시고, 아래 순서대로 터미널을 열어 명령어를 입력해 주세요.

1. 윈도우 작업 표시줄 왼쪽의 **돋보기(검색창)**를 누릅니다.
2. 영어로 **`PowerShell`** (또는 한글로 **파워쉘**)을 검색합니다.
3. 결과에 나오는 **'Windows PowerShell'** 위에서 **마우스 우클릭 ➡️ [관리자 권한으로 실행]**을 클릭합니다. (★ 중요: 꼭 관리자 권한이어야 숨은 프로세스가 죽습니다.)
4. 파란색 터미널 창이 뜨면, 아래 명령어를 **그대로 복사(`Ctrl+C`)해서 마우스 우클릭으로 붙여넣고 엔터**를 누릅니다.

powershell

```
Stop-Process -Name "antigravity*" -Force; Stop-Process -Name "Code*" -Force; Stop-Process -Name "language_server*" -Force
```

코드를 사용할 때는 주의가 필요합니다.

_(※ 만약 해당 프로세스가 이미 죽어있다면 "프로세스를 찾을 수 없다"는 빨간 글씨 에러가 뜨는데, 이는 이미 잘 닫혔다는 뜻이니 전혀 신경 쓰지 않으셔도 됩니다.)_

🏃‍♂️ 그다음 처리 단계

1. 위의 명령어를 실행한 뒤, 화면에 떠 있던 **VS Code 업데이트 에러 팝업창으로 돌아가 [다시 시도(Retry)]**를 누릅니다.
2. 만약 [다시 시도]를 눌러도 창이 안 넘어가거나 먹통이라면, 컴퓨터를 **[다시 시작(재부팅)]** 해보세요.
3. 재부팅 직후 아무 프로그램도 켜지 않은 상태에서 안티그래비티 설치 파일을 실행하면 100% 정상 업데이트가 완료됩니다. [](https://discuss.ai.google.dev/t/issue-with-updates-from-1-19-4-to-1-19-5-update-fails-with-error-due-to-visual-code-file/126953)

관리자 권한 파워쉘에 명령어를 입력하고 에러 창의 **[다시 시도]**를 누르셨을 때, 드디어 업데이트가 막힘없이 진행되었나요? 만약 여전히 안 된다면 화면에 나오는 **정확한 파일 경로(예: C:\Users...)나 에러 문구**를 알려주세요. 무조건 해결해 드릴게요


VS Code 업데이트 에러 팝업창을 닫았는데?

구글 로그인이 안 되어 있어도, 우리가 열심히 설정해 둔 **Ollama(`127.0.0.1:11434`)와 Gemma 4:E4B 모델 연동망은 완벽하게 독자 작동**합니다. 지금 안티그래비티 채팅창에 아무 질문이나 입력해 보세요. 글자가 실시간(Stream)으로 주르륵 잘 내려온다면 이미 세컨드 브레인 AI 비서는 완벽하게 출근해 있는 상태입니다! 로그인은 인프라 작동에 아무런 방해를 주지 않으니 편하게 무시하고 메모 시스템 구축을 즐기셔도 됩니다.

제어판에서 구글/안티그래비티 자격 증명을 지우거나 `Auth` 명령어를 쳤을 때 크롬 창이 반응하나요? 로그인을 진행하지 않더라도 **현재 AI 채팅창에 질문을 던졌을 때 Gemma 4 모델이 대답을 실시간으로 훌륭하게 잘 주는지** 최종 확인 결과를 편하게 말씀해 주세요!

웹페이지(크롬)에서는 로그인이 완료되었다고 뜨는데 안티그래비티 앱이 묵묵부답인 이유는, ==**크롬 브라우저가 로그인 인증 토큰을 안티그래비티 앱으로 던져줄 때 윈도우의 '앱 연결 통로(Protocol Handler)'가 차단되어 신호를 전달받지 못했기 때문**==입니다. [](https://discuss.ai.google.dev/t/antigravity-login-loop-oauth-redirect-fails-windows-protocol-handler-issue/142153)


최근 안티그래비티 커뮤니티에서도 **"OAuth 인증은 성공하는데 앱으로 리다이렉트(되돌아가기)가 안 된다"**며 수많은 개발자가 겪고 있는 아주 유명한 버전 버그입니다. [](https://discuss.ai.google.dev/t/antigravity-login-issue-browser-not-redirecting-to-application/132439)

아 그리고 mcp 작동 확인 안했어요

맞습니다! 가장 중요한 **MCP(Model Context Protocol) 작동 확인** 단계가 남았었네요.

D 드라이브로 수동 업데이트를 하면서 안티그래비티가 초기화된 것처럼 보여도, 저희가 진짜 장부 주소인 `C:\Users\Owner\_.gemini\config\mcp_config.json`에 코드를 심어놓았기 때문에 **설정 자체는 그대로 살아있을 확률이 매우 높습니다.**

안티그래비티와 LM Studio/Ollama 브릿지(MCP)가 정상적으로 맞물려 일하고 있는지 확인하는 **가장 확실한 3단계 체크법**을 알려드릴게요.

---

🔍 1단계: 에이전트 패널에서 '초록불' 확인하기 (가장 간편)

1. 안티그래비티 IDE 우측에 있는 **에이전트 사이드 패널(Agent side panel)**을 봅니다.
2. 패널 상단의 **`...` (더보기) 버튼**을 누른 뒤 **`MCP Servers`** (또는 Manage MCP Servers) 메뉴로 들어갑니다.
3. 목록에 저희가 등록했던 **`lmstudio-mcp`** 가 있는지 확인합니다.
4. 이름 옆에 **초록색 동그라미 불(Connected)**이 켜져 있다면 백그라운드 연결은 완벽하게 성공한 상태입니다. [](https://discuss.ai.google.dev/t/how-to-fix-this-mcp-server-error/173053)


---

💬 2단계: 대화창에 명령어로 직접 물어보기 (치트키)

UI 메뉴를 일일이 누르기 번거로우시다면, 안티그래비티 채팅창에 직접 시스템 명령어를 입력해 상태를 조회할 수 있습니다. [](https://sight-r.sts-inc.co.jp/google_cloud_article/antigravity-mcp-guide/)

- 안티그래비티 대화창(CLI/Chat)에 **`/mcp`** 라고 입력하고 엔터를 쳐보세요.
- **MCP 매니저 화면**이 팝업되면서 현재 연결된 서버 목록, 연결 상태(Status), 연결 로그가 한눈에 시원하게 출력됩니다. 여기에 `lmstudio-mcp`가 정상(Active)으로 뜨면 합격입니다. [](https://sight-r.sts-inc.co.jp/google_cloud_article/antigravity-mcp-guide/)

---

🛠️ 3단계: AI 비서에게 실제 "도구 사용" 테스트하기 (최종 검증)

장부만 켜져 있고 실제 통신이 안 되는 경우를 대비해, 로컬 모델에게 MCP 도구를 강제로 꺼내 쓰도록 유도 명령을 던져보는 것이 가장 확실합니다.

채팅창에 아래 문장을 그대로 복사해서 질문해 보세요.

> **"너한테 연결된 MCP 서버 도구 목록(Tools)이 뭐가 있는지 나한테 전부 리스트로 출력해 줘."**

- **정상 작동할 때:** Gemma 4 모델이 내부적으로 MCP 브릿지를 팅겨서 도구들을 탐색한 뒤, _"현재 `lmstudio-mcp` 서버를 통해 제공되는 OO, OO 도구들이 있습니다."_ 하고 명확하게 답변합니다.
- **오류가 날 때:** 빨간색 에러 메시지가 뜨거나, _"사용 가능한 도구가 없습니다"_ 혹은 `Git operation failed` 같은 이전의 에러가 다시 출력됩니다. [](https://discuss.ai.google.dev/t/how-to-fix-this-mcp-server-error/173053)

💡 만약 빨간 불이 들어와 있거나 에러가 난다면?

수동 업데이트 과정에서 파이썬 실행 경로(`%PATH%`) 인식이 잠시 풀렸을 수 있습니다.

그럴 때는 당황하지 마시고 **오른쪽 패널 `...` 메뉴 ➡️ Manage MCP Servers** 화면으로 가셔서 **`Refresh(새로고침)` 버튼**을 누르거나, 안티그래비티 창을 껐다가 다시 켜주시면(`Developer: Reload Window`) 꼬여있던 연결이 다시 깔끔하게 붙을 것입니다. [](https://antigravity.google/docs/mcp/)

채팅창에 **`/mcp`** 를 입력하셨을 때 목록이 잘 나오나요? 아니면 AI에게 **도구 목록을 물어봤을 때 Gemma 4 모델이 도구 리스트를 정상적으로 잘 대답하는지** 최종 테스트 결과를 알려주세요!


초록색 동그라미가 없고 더보기에도 settings 만 있고 mcp가 없어요 근데 설정에 들어가니 로그인되있는 창이 있네요

**오호, 아주 중요한 단서를 발견하셨습니다! 설정에 구글 계정이 정상적으로 로그인되어 있는 상태이시군요!** (아까 웹페이지에서 시도했던 로그인이 뒤늦게 윈도우 장부에 반영되어 성공한 것입니다. 정신 건강을 챙기니 알아서 풀렸네요! ㅎㅎ) [](https://antigravity.google/docs/mcp/)

현재 화면 우측 패널 더보기에 `MCP` 메뉴와 초록불이 보이지 않는 이유는, 수동 업데이트 과정에서 안티그래비티의 **화면 레이아웃(UI)이 '일반 코딩 모드'로 초기화되면서 에이전트 전용 메뉴들이 숨겨졌기 때문**입니다. 장부는 살아있으니 메뉴판만 다시 꺼내주면 됩니다.

1. 안티그래비티 IDE 화면 **왼쪽 최하단에 있는 톱니바퀴 모양의 [Settings(설정)]** 메뉴를 클릭합니다.
2. 설정 창이 열리면 왼쪽 탭 중에서 **`Customizations` (커스텀)** 이라는 메뉴를 클릭합니다.

4. 이 명령을 실행하면 화면에 곧바로 내 로컬 서버와 연동된 MCP 장부 페이지가 짜잔 하고 강제로 열리게 됩니다. [](https://antigravity.google/docs/mcp/)
